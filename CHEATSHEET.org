#+TITLE: Datum Cheatsheet
#+OPTIONS: toc:nil num:nil

* Quick Start

With the recommended setup, getting from zero to a SQL editing buffer takes
two steps:

1. =M-x sql-connect= (or =M-x sql-datum=) — connect to a database
2. =C-c q= — open a scratch SQL buffer, ready to query

From the scratch buffer you have full completion (=TAB=), all the =C-c s= /
=C-c t= keybindings, and =C-c C-r= / =C-c C-b= to send SQL to the server.

** Recommended init file settings

#+begin_src emacs-lisp
(require 'sql-datum)
(autoload 'sql-datum-scratch "sql-datum" nil t)
(global-set-key (kbd "C-c q") #'sql-datum-scratch)
(add-hook 'sql-mode-hook
          (lambda () (setq-local tab-always-indent 'complete)))
#+end_src

directly.

* Completion

- =TAB= completes tables, schemas, routines, columns, databases
- Column completion is *contextual*: when your statement has =FROM= /
  =JOIN= / =UPDATE= / =INTO=, only those tables' columns are offered
- Scans full statement (before + after point): =SELECT <TAB> FROM
  customers= narrows to =customers= columns
- Uncached columns are fetched silently on first =TAB=; second =TAB=
  shows contextual results
- Multi-table: =FROM t1 JOIN t2 WHERE <TAB>= shows columns from both
- No =FROM= yet? Falls back to all cached columns
- Context columns are sorted before tables in the completion list
- Identifiers with spaces are auto-quoted: ="my col"= (PostgreSQL), =[my col]= (MSSQL)
- Typing ="che<TAB>= or =[che<TAB>= matches and quotes correctly
- Qualified: =table.<TAB>= or =alias.<TAB>= offers =table.column= candidates
- Aliases resolved: =FROM users u WHERE u.<TAB>= shows =users= columns
- MSSQL cross-database: =otherdb.<TAB>= fetches that database's objects

* Running Queries Buffer

Shows session ID, user, status, duration, and SQL text.
Respects =:chars= for column width. Timestamp shows last refresh.

| Key | Action               |
|-----+----------------------|
| =g= | Refresh              |
| =a= | Toggle auto-refresh  |
| =q= | Quit                 |

* Admin Panels (=C-c s a=)

Panels for server administration.  The available keys are shown in each
panel's header line, which stays visible as the contents scroll.

Panels: =activity=, =databases=, =jobs=, =schema=, =security=, =ssis=

Tables view (=T=):

| Key | Action              |
|-----+---------------------|
| =N= | New table (builder) |
| =E= | Alter columns       |
| =D= | Drop table          |

The builder takes columns as a list — name, type, nullable, primary key,
default — with =[INS]= / =[DEL]= to add and remove rows.  =TAB=
completes a type while there is more to complete, then moves on; an
unlisted size such as =VARCHAR(120)= is fine too.  =E= edits an existing table's columns the same way and applies
only what changed; editing a name in place renames the column and keeps its data, while
removing a row and inserting another drops and adds.  Anything that
drops a column shows the plan and asks for the table name first.

* Connection Examples

#+begin_src shell
# PostgreSQL
datum --driver "PostgreSQL Unicode" --server localhost --database mydb --user postgres --pass ENV=PG_PASS

# MSSQL integrated auth
datum --driver "ODBC Driver 18 for SQL Server" --server myserver --database mydb --integrated

# SQLite
datum --driver SQLite3 --database /path/to/db.sqlite

# DSN
datum --dsn MyDSN

# Connection string
datum --conn-string="Driver={PostgreSQL Unicode};Server=localhost;Database=mydb;Uid=postgres;Pwd=secret"
#+end_src

* Custom Commands

#+begin_src ini
[queries]
top=SELECT * FROM {table} LIMIT {how_many}
find=SELECT * FROM {table} WHERE {field} = ?
#+end_src

={placeholder}= is prompted and string-formatted. =?= is an ODBC parameter (escaped).
